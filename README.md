# blogbot — 네이버 블로그 글쓰기 도우미

예전에 쓴 원고로 **말투·구성·흐름을 학습**해서, 이번에 겪은 일(메모)과 새 사진으로 새 글 초안을 만들고,
네이버 노출에 불리한 점을 검사한 뒤, 네이버 블로그 에디터에 **채워 주는** 프로그램입니다.
최종 [발행]은 기본적으로 사람이 누릅니다.

```
data/manuscripts/ (예전 원고) ─┐
data/photos/      (예전 사진) ─┼─ learn ─▶ 문체 프로필 + 문체 통계 + 사진 설명
data/new_photos/  (새 사진)   ─┘
                                        │
주제·키워드·메모(이번 경험)·새 사진 ─── write ─▶ 초안 → 검사 → 편집 패스 → 사진 가공
                                        │           output/drafts/<초안>/preview.md
                                        ▼
                                     publish ─▶ 에디터에 글·사진·태그·발행 설정 채움 → 사람이 [발행]/[예약]
                                        │
                                   (1~2일 뒤) check ─▶ 검색에 나오는지 확인·기록, 연속 누락 시 발행 중단
```

## 설치

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium

cp config.example.yaml config.yaml      # 블로그 ID, 사업 정보, 블로그 주제 등 수정
cp .env.example .env                    # ANTHROPIC_API_KEY 입력
```

## 사용법

```bash
# 0) 자료 넣기
#    data/manuscripts/ : 예전 원고 (.txt / .md / .docx). 파일명 앞에 날짜(20240315-...)가 있으면 최근 글 문체를 우선합니다.
#                        .docx 는 사진 위치도 읽어서 사진 배치 습관까지 학습합니다.
#    data/photos/      : 예전에 블로그에 올렸던 사진
#    data/new_photos/  : 아직 어디에도 안 올린 사진

# 1) 문체 학습 + 사진 분석 (원고가 바뀌면 다시 실행)
python -m blogbot learn

# 2) 네이버 로그인 (최초 1회, 열린 브라우저에서 직접)
python -m blogbot login

# 3) 초안 작성 — --notes 에 이번 글만의 새 정보를 적는 것이 가장 중요합니다
python -m blogbot write --topic "가을 신메뉴 소개" --keyword "밤라떼" --sub-keywords "강남 카페,가을 신메뉴" \
    --notes "9/25 밤라떼 출시, 5,500원. 처음엔 너무 달아서 페이스트를 20% 줄임. 따뜻한 게 더 맛있음" \
    --photos ~/Pictures/밤라떼

# 4) output/drafts/<초안>/preview.md 확인 → 필요하면 post.json 수정 → 다시 검사
python -m blogbot lint output/drafts/<초안폴더>

# 5) 에디터에 채우기 → 브라우저에서 확인 후 직접 [발행] 또는 예약
python -m blogbot publish output/drafts/<초안폴더>

# 6) 발행 1~2일 뒤: 검색에 나오는지 확인
python -m blogbot check

python -m blogbot drafts     # 초안 목록과 상태
```

## 네이버 노출을 위해 이 프로그램이 하는 일

네이버가 공식적으로 밝힌 검색 체계는 **C-Rank**(블로그 단위: 한 주제에 대한 집중도·품질·반응),
**D.I.A.+**(글 단위: 주제 적합도·경험 정보·충실성·의도·독창성·적시성·어뷰징 척도), **유사문서 판독**이고,
2025년 2월 공지에서 여기에 LLM 평가를 더해 "자동 생성된 저품질 콘텐츠나 실제 경험에 기반하지 않은 광고성 글"을
걸러낸다고 밝혔습니다. 2026년 5월 네이버 검색 가이드는 유리한 글로 **직접 경험 · 일관된 주제 · 진정성 ·
읽기 쉬운 구조 · 최신성**을, 불리한 글로 **반복 키워드 · 낚시성 제목 · 짜깁기 · 기계적 AI 생성 · 과도한 홍보**를
꼽았고, AI 도구를 썼다는 것만으로 불이익은 없다고 했습니다.

| 네이버 기준 | 프로그램이 하는 일 |
| --- | --- |
| 직접 경험 | `--notes` 필수. 메모에 없는 경험·감각 묘사·수치는 쓰지 않고 `[확인필요]`로 남김. 글 속 모든 구체 정보의 출처를 표시하게 하고, 출처 없는 정보가 있으면 발행 차단 |
| 일관된 주제 | `business.topics` 안에서 쓰도록 지시, 발행 카테고리 고정 |
| 진정성 | 사업 정보·메모 밖 사실 금지, 효능·최상급 표현 경고, 손님 후기가 아니라 운영자 시점으로 작성 |
| 읽기 쉬운 구조 | 첫 문단에 답 먼저, 소제목(에디터 소제목 서식으로 입력), 긴 문단·사진 연속 경고 |
| 최신성 | 오늘 날짜를 알려주고 가격 등 옆에 기준 시점 표기, 1년 넘은 사진 경고 |
| 유사문서 (글·사진) | 예전 원고 **및 이 프로그램으로 올린 글** 각각과 문장 겹침 검사 (15% 넘으면 차단), 같은 제목 차단, 소제목 구성 반복 경고, 예전 사진은 글당 1장 |
| 반복 키워드 · 낚시 제목 | 키워드 과다·제목 낚시어·특수문자 시작 경고 |
| 기계적 AI 생성 | 문체 통계(문장 길이·ㅎㅎ·이모지 빈도)와 비교, AI 상투구 검사, 검사 결과를 받은 편집자가 지적된 곳만 한 번 더 고침 |
| 과도한 홍보 · 참여 유도 | 이웃추가·공감·댓글 이벤트 문구 차단, URL 2개 이상 차단, 가게 이름 반복 경고 |

**수치에 대해**: 글자수·키워드 횟수·제목 길이·사진 수는 네이버 공식 기준이 없고, 실제 상위 글도 수백~수천 자,
사진 몇 장~수십 장으로 다양합니다. 그래서 이런 수치는 모두 '경고'일 뿐 발행을 막지 않습니다.
가장 믿을 만한 기준은 **내 키워드로 검색했을 때 상위 글 5~7개**입니다. 그 글들의 분량·사진 수를 직접 보고
`writing.length_no_space`, `images_per_post` 를 맞추세요.

## 사진

- 네이버 유사문서 판정은 **사진도 비교**합니다 (이미지 1장이 비교 단위 1개). 크롭·색보정·해시 변경으로 같은
  사진임을 숨길 수 있다는 근거는 없습니다. 그래서 이 프로그램은 사진을 속이는 가공을 하지 않고,
  **같은 사진을 자주 쓰지 않는 것**으로 대응합니다.
  - `data/photos`(예전에 올린 사진)는 이미 1번 쓴 사진으로 계산하고, 한 글에 최대 1장만 씁니다.
  - 새 사진은 최대 2번, 90일 간격으로만 다시 씁니다. 사진은 파일 내용으로 식별하므로 이름을 바꿔도 이력이 유지됩니다.
  - 새 사진이 없으면 경고합니다. **이번 글을 위해 새로 찍은 사진(`--photos`)이 노출에 가장 좋습니다.**
- 가공은 품질용입니다: 방향 보정, sRGB 색 변환(아이폰 사진 색 바램 방지), 긴 변 2000px 로 축소(작은 사진은
  확대하지 않음), 약한 샤픈, 선택적 작은 워터마크.
- 촬영 기기·GPS 정보는 **개인정보 보호를 위해** 지웁니다. 이것이 노출에 영향을 준다는 근거는 없습니다.
- AI 생성 이미지나 스톡 이미지는 쓰지 않습니다 (직접 경험 신호와 정면으로 충돌).

## 계정 제재 위험을 줄이기 위해

네이버는 2020년 5월 블로그 글쓰기 API 를 종료했고, 이용약관(2018년 개정)은 **매크로 등 자동화된 수단으로
게시물을 게재하는 것**을 금지합니다. 브라우저로 에디터를 채우는 것도 여기에 해당할 수 있습니다. 위험을 없앨 수는
없어서, 이 프로그램은 위험을 줄이는 쪽으로만 동작합니다:

- **기본은 review 모드**: 글·사진·태그·카테고리·전체공개·검색허용까지 채우고 멈춥니다. [발행]이나 예약은 사람이 누릅니다.
  `draft` 모드는 네이버 임시저장까지만 하고, 임시저장함에서 열어 직접 예약 발행하면 됩니다.
- 자동 발행(`publish`)은 `naver.allow_auto_publish: true` 를 직접 켜야만 동작하고, 발행 설정을 확인하지 못하면 멈춥니다.
- 로그인은 직접 합니다 (비밀번호를 저장하지 않음). 항상 같은 브라우저 프로필을 쓰고, 화면이 보이는 브라우저만 씁니다.
- 보호조치·이용제한·로그인 만료 화면을 만나면 **즉시 멈추고 재시도하지 않습니다**. 캡차는 사람이 풉니다.
- 발행량 제한: 최근 24시간 1건, 7일 4건, 발행 간격 20시간. 명령행 옵션으로 넘길 수 없습니다.
- 글쓰기 화면 말고는 아무 페이지도 자동으로 돌아다니지 않습니다 (공감·댓글·이웃 자동화 없음, 검색 결과 수집 없음).
- 탐지 회피 기능(사람처럼 타이핑 흉내, 브라우저 지문 위장 등)은 넣지 않았습니다. 효과 근거도 없고 약관 위반 소지를 키웁니다.
- 한 계정은 한 기기에서, VPN/IP 바꾸기나 여러 계정 돌리기는 하지 마세요.

## 검색 누락 확인 (`check`)

발행 24시간 뒤부터, 제목을 큰따옴표로 감싼 네이버 블로그 검색 주소를 보여줍니다. 열어서 내 글이 보이는지
직접 확인하고 y/n 으로 기록합니다 (프로그램이 네이버 검색을 긁지 않습니다). 최근 2개 글이 연속으로 안 나오면
발행을 멈춥니다. 이때는 고객센터 '검색 반영 요청'을 하고, 최근 글에 새 경험 정보가 충분했는지·예전 글이나 사진과
겹치지 않았는지 점검한 뒤 `python -m blogbot check --resume` 으로 풉니다.

참고: 네이버는 '저품질 블로그'라는 등급은 없다고 밝히고 있습니다. 흔히 저품질이라 부르는 현상은 검색 스팸 필터,
유사문서 필터, 랭킹 하락, 계정 이용제한이 섞인 것입니다.

## 처음 실행할 때

- SmartEditor 화면 구조는 자주 바뀝니다. **처음에는 `review` 모드로, 가능하면 테스트 계정에서** 제목·본문·사진·
  소제목·태그·카테고리가 제자리에 들어가는지 확인하세요. `--debug` 를 붙이면 단계별 스크린샷을 초안 폴더에 남깁니다.
  어긋나면 `config.yaml` 의 `naver.selectors` 로 셀렉터를 바꿀 수 있습니다.
- 공정위 표시 문구(협찬·운영자 표기 등)는 프로그램이 넣지 않습니다. 필요하면 review 단계에서 직접 넣어 주세요.
- 에디터가 빠른 입력을 놓치는 경우가 있어, 제목이 제대로 들어갔는지 확인하고 아니면 자동으로 한 글자씩 입력합니다
  (`naver.input_method`). 이 지연은 에디터가 글자를 받아들이게 하려는 것이고, 사람 흉내가 아닙니다.

## 개발

```bash
pip install pytest
python -m pytest -q
```

테스트는 Claude API 를 호출하지 않고(응답을 가짜로 대체), 네이버에도 접속하지 않습니다.
`tests/test_publisher_mock.py` 는 SmartEditor 를 흉내 낸 가짜 페이지로 입력·발행 흐름을 검증합니다
(크로미움 경로는 `BLOGBOT_TEST_CHROMIUM`). 실제 네이버 셀렉터가 맞는지는 review 모드 첫 실행에서 확인해야 합니다.

구성: `corpus.py`(원고·유사도·문체 통계) · `style.py`(문체 프로필) · `photos.py`(사진 인덱스·사용/발행 기록) ·
`images.py`(사진 가공) · `writer.py`(글 생성·검사·편집) · `publisher.py`(에디터 입력) · `cli.py`(명령어)
